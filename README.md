# BotsDoThat

> There's a bot for that. Here's how.

A live, always-up-to-date hub of real AI agent use cases for non-technical people, plus "build your own bot" blueprints.
Plain HTML/CSS/vanilla JS output, generated by a stdlib-only Python script.

**Live:** https://botsdothat.com/ (custom domain, HTTPS enforced; old github.io links redirect) · **Repo (public):** https://github.com/nik-schultz/agents-on-radar · **Deploy:** `scripts/deploy.sh "what changed"`

**Brand:** BotsDoThat (picked Oct 21, 2026; was "Agents on Radar"). Live on **https://botsdothat.com/** since Oct 21, 2026 (bought by Nik on Cloudflare; DNS-only records to GitHub Pages; runbook in `ops/domain_cutover.md`). The repo keeps the old `agents-on-radar` slug.

**Rename in one line:** change `site_name` in `config.json`. Titles, logo, og image, RSS and llms.txt
follow. The site URL comes from `base_url` (now `https://botsdothat.com/`, with `cname` botsdothat.com). A path in it becomes the base path for every link, asset, canonical, sitemap, RSS, llms.txt and og URL.

## Quick start
```bash
python3 scripts/build.py                 # writes site/
python3 scripts/check_links.py           # internal link check (add --external to HEAD-check outside links)
python3 -m http.server 8090 -d site      # preview at http://localhost:8090/
```

## Structure
```
config.json               site name (BotsDoThat), tagline + subtagline, base_url/base_path, newsletter form, trending window
data/categories.json      8 categories (slug, name, icon, art slot, blurb)
data/tools.json           tool registry (chat / agent / automation) with cost notes and official links
data/use-cases.json       all use cases (schema below)
data/blueprints.json      12 build-your-own-bot blueprints
data/sponsors.json        sponsor slots: featured_home, featured_category, use_case_sidebar (empty = house ad)
data/incoming/            drop new use cases here for the daily routine (see _template.json.example)
data/popularity-history.jsonl   append-only log of every measured number
scripts/build.py          generator (pages, search index, RSS, sitemap, robots, llms.txt, og.png)
scripts/validate.py       schema + honesty checks (popularity must be measured integers with url + date)
scripts/add_use_cases.py  appends data/incoming/*.json → data/use-cases.json
scripts/refresh_popularity.py   merges real X / Reddit numbers into popularity
scripts/check_links.py    link checker
scripts/optimize_images.py  art/incoming/* → static/img/*.webp
scripts/daily.sh          the whole daily routine in one command
static/                   style.css, app.js, favicon.svg (+ img/ when art exists)
art/PROMPTS.md            exact image prompts for every art slot
research/                 seed scripts, raw X data, RDAP name checks, sources
previews/                 screenshots (git-ignored)
```

## Use case schema (data/use-cases.json)
| field | notes |
|---|---|
| slug, title, category | category must exist in categories.json |
| date_added | ISO date it entered the hub (drives "Just added" and RSS) |
| source_date | ISO date of the source post/article (or null) |
| summary | 1–2 plain sentences |
| what_the_bot_does | list of plain steps |
| what_you_end_up_with | the concrete result |
| difficulty | Easy / Medium / Advanced |
| tools | `[{id, note?}]`, ids from tools.json |
| prompt | copy-paste prompt with [brackets] |
| setup, watch_out, tags | optional lists |
| sources | `[{label, url, kind: x/reddit/article/official}]`, at least one |
| popularity | **null** unless measured. X: `{platform:"x", post_id, author, url, posted_at, likes, reposts, replies, bookmarks, views, measured_at}`. Reddit: `{platform:"reddit", url, author, posted_at, upvotes, comments, measured_at, note?}` |
| guide, faq, real_examples | optional (migrated long-form guides) |

**Trending heat** = (likes + 2×reposts, or upvotes) ÷ (weeks since posted), posts older than `trending_window_days` (60) score 0.

## Daily routine (for the agent that keeps the hub live)
1. **Find new use cases.** Search X (`x` namespace `search_posts_all`, `post.fields=public_metrics,created_at`, `expansions=author_id`,
   `user.fields=username`, `start_time` = 2 days ago), Reddit and the web. Write each new entry as JSON in
   `data/incoming/<date>-<slug>.json` using `data/incoming/_template.json.example`. Copy likes/reposts exactly from the API
   response and set `measured_at`; if you can't measure it, set `"popularity": null`.
2. **Refresh numbers.** `python3 scripts/refresh_popularity.py --export-ids` prints tracked X ids (≤100 per line).
   Call `get_posts_by_ids` with each line (`post.fields=public_metrics,created_at`, `write_to_file: true`) and keep the files.
3. **Run everything:**
   ```bash
   scripts/daily.sh /workspace/agent-tools/<metrics-file-1>.txt [more files]
   ```
   = validate → add incoming → merge metrics → validate → build → link check. Rejected entries go to
   `data/incoming/rejected/` with a `.err` file explaining why.
4. Review `git diff data/`, then deploy: `scripts/deploy.sh "Daily update YYYY-MM-DD"`. Routine deploys are approved. The script commits, publishes and prints the live URL; see Deploy below.

Reddit numbers: Reddit blocks reads from this box. If you get counts another way, write JSON lines
`{"url","upvotes","comments","measured_at"}` and run `python3 scripts/refresh_popularity.py --from-reddit file.jsonl`.

## Latest in AI (daily news update)
`data/news.json` feeds the "Latest in AI" tiles on the homepage (top story + 3 trending + newest), plus `/news/` (Top story mega-tile, Trending tiles, This week / Earlier grids, filter chips), `/news/feed.xml`, the sitemap and llms.txt.
Daily routine:
1. Check the official newsrooms and changelogs: openai.com/news + developers.openai.com/api/docs/changelog, anthropic.com/news + claude.com/resources, blog.google (Gemini) + ai.google.dev/gemini-api/docs/changelog, x.ai/news + docs.x.ai/developers/release-notes, research.meta.ai / dev.meta.ai blog, mistral.ai/news, api-docs.deepseek.com/updates, groq.com/blog. Also check reputable outlets (TechCrunch, The Verge, SiliconANGLE, 9to5Google, Reuters/CNBC) for agent launches and agent features.
2. Add only items you actually opened. Fields: `id` (slug), `date` (publish date shown on the source), `category` (model release | agent launch | feature | pricing | industry), `company` (OpenAI, Anthropic, Google, xAI, Meta, Mistral, DeepSeek, Groq; this sets the tile colour/monogram, and new companies need an entry in `NEWS_CO` in build.py), `impact`, a plain-words `headline`, a 1-2 sentence `explainer` (the first sentence is the one-line "For you" on small tiles), `source_url`, `source_name`, and optional `more_sources`.
3. **`impact` is importance, not popularity.** `major` = a new flagship model or a major agent launch from a big lab (OpenAI, Anthropic, Google, Meta, xAI). `minor` = changelog-level tweaks (a billing detail, a tool price, a UI move, infrastructure code). `notable` = everything else.
4. **Capture X engagement** with the X public read tools. Respect the rate limit (about 30 reads a minute; one `search_posts_all` call returns up to 25 posts).
   - Find the announcing post. Search `from:<account> -is:reply -is:retweet` from the launch date with `post.fields=created_at,public_metrics`. Accounts used so far: OpenAI, OpenAIDevs, AnthropicAI, claudeai, GoogleDeepMind, GeminiApp, googlecloud, AIatMeta, MistralAI, deepseek_ai, elonmusk (xAI has no active company account in search; Elon Musk's own post is the founder fallback), and bot (Grok Bot).
   - If there's no official post, search the product name (`"Grok Voice" -is:retweet -is:reply`, `sort_order=relevancy`). Use the most-engaged post from a credible account (e.g. a benchmark org or reporter) and set `kind: "coverage"`. Skip anonymous hype accounts. No good post means no `x` block; never estimate.
   - Re-measure with `get_posts_by_ids` (up to 100 ids in one call). Record `x = {url, author "@handle", kind official|coverage, likes, reposts, views (impression_count), posted_at, measured_at}`. Save the raw API response under `research/` as `*.json.txt`. It stays local (gitignored, never published); see `research/news_x_2026_10_21.py` for how it's applied.
   - Refresh the numbers on the trending items about once a week, because heat decays with age.
5. Ranking is automatic in build.py. **Heat** = (likes + 2 × reposts) ÷ (weeks since posted), the same formula as use-case trending, with a 60-day window. **Top story** = the hottest `major` item of the last 14 days (falls back to 30 days, then to the hottest item). **Trending** = the top 3 by heat, excluding the top story.
6. If an item changes a model's price, update `data/ai-pricing.json` from the official page (see above) in the same run.
7. Run `validate.py` → `build.py` → `check_links.py`. The validator errors on items with a missing date, source, category, company, impact or explainer, and on any `x` block without real integers, @author, kind, posted_at and measured_at. It warns when the newest item is more than 3 days old.
No invented items, dates or numbers. If you can't confirm a date, leave the item out.

## AI price table (weekly refresh)
`data/ai-pricing.json` feeds `/ai-pricing/`, the `/run-your-bots-for-less/` hub and the "What this costs to run" note on every blueprint (blueprint token assumptions live in each blueprint's `cost` field).
Once a week: open every `source_url` (official pricing pages only), update the numbers, notes (watch promo end dates) and `checked_on`, then `validate.py` + `build.py`.
If a price can't be read on the official page, remove the row and list it under `not_verified`. Never estimate a price. `validate.py` warns when the file is more than 7 days old.

## Images
CSS art slots render until real images exist. Prompts: `art/PROMPTS.md`. Put PNG/JPG into `art/incoming/<slot>.png`,
run `python3 scripts/optimize_images.py`, rebuild. og.png is generated at build time (Pillow) and uses `og-bg.webp` if present.
Status 2026-10-20: all 10 slots are live (about 190 KB of WebP in total). The homepage radar uses a square `hero-radar.webp` crop
(the centre is set in `HERO_RADAR` in optimize_images.py) and hides the CSS rings when it's present. Below-the-fold images use `loading=lazy`.

## Newsletter and sponsors
Newsletter: paste your provider's form POST URL into `config.newsletter.form_action`; until then the form is disabled.
Sponsors: add an object `{name, headline, body, url, cta, categories?}` to a slot in `data/sponsors.json`; it renders labeled "Sponsored" with `rel="sponsored"`.

## Deploy (live on GitHub Pages)
- Live: https://botsdothat.com/ (Pages custom domain, Enforce HTTPS on) · Repo: https://github.com/nik-schultz/agents-on-radar (public). Pages source: GitHub Actions.
- **Deploy command:** `scripts/deploy.sh "Short description"`. It runs validate → build → link check, commits everything on local `main`, then adds one squashed commit to the local `publish` branch (same tree as `main`) and runs `git push origin publish:main`. The push triggers `.github/workflows/pages.yml`, which re-runs `validate.py` and `check_links.py` on the committed `site/` and publishes it unchanged, so Pillow isn't needed in CI. It's live about 1 minute later.
- Watch / verify: `gh run list -R nik-schultz/agents-on-radar -L1`, then `gh run watch <id> -R nik-schultz/agents-on-radar --exit-status`. Spot-check with `curl -sI https://botsdothat.com/news/`.
- **Why two histories:** local `main` still contains the raw art PNGs in old commits, and those stay private. The public repo only gets the small `publish` history. Never run `git push origin main`. The script refuses to publish if `art/incoming/`, raw `research/*.json.txt` / `x_posts_full.json` API dumps, `.env`, keys or logs are tracked. Those paths are in `.gitignore`: raw X API responses saved by the routines stay local, and only the extracted numbers go into `data/`.
- Contact: `contact_email` is empty, so contact links go to `contact_url` (GitHub issues). Don't set an email on a domain we don't own.
- Custom domain later: set `base_url` to `https://<domain>/` and `cname` to the domain, rebuild and deploy, then add DNS. robots.txt only counts at a domain root, so it matters again once there's a custom domain. Sitemaps are still found through the robots.txt link and llms.txt.
